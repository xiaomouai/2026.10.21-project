# 周复盘 · Weekly Review

> 每周五 17:00 固定执行，约 60 分钟。目标是「判断哪些该加码、哪些该砍掉」。

## 执行步骤

### 1. 数据汇总（10 min）
```bash
python scripts/weekly_review.py
```
自动产出：本周数字、环比上周、逐篇内容归因。

### 2. 逐篇归因（20 min）
对本周每篇内容，回答 3 个问题：
1. **阅读**怎么样？（选题/标题问题 → gzo-topic）
2. **CTA 点击/加微**怎么样？（钩子/承接问题 → gzo-content / gzo-convert）
3. **成交贡献**怎么样？（销售/产品问题 → gzo-product）

→ 填 `templates/weekly-review-template.md`。

### 3. 验证选题假设（15 min）
翻 `experiment-log.csv`，把每个 `假设` 标记为：
- ✅ **验证有效** → 提炼原子，下周加码同类
- ❌ **验证无效** → 记录失败原因，加入「反向原子」
- ⏳ **待观察** → 给到下周

### 4. 提炼与归档（15 min）
- 有效原子 → `knowledge/` 追加。
- 本周决策 → `archive/YYYY-MM/decisions.md`。
- 调用 `gzo-archive` 完成沉淀。

## 周复盘输出模板

```markdown
# 周复盘 · YYYY-W[ww]（MM/DD - MM/DD）

## 一、本周数字
| 维度 | 本周 | 上周 | 环比 |
| 流量 | 阅读 / 分享 / 新增关注 | | |
| 销售 | 线索 / 有效沟通 / 成交 / GMV | | |
| 产品 | 交付 / NPS / 退款 | | |

## 二、内容归因
| 选题 | 阅读 | CTA点击 | 加微 | 成交 | 结论 |
|...

## 三、假设验证
- ✅ [选题] → 加码方向
- ❌ [选题] → 失败原因
- ⏳ [选题]

## 四、淘汰清单（下周停止做）
- [渠道/选题/动作]：原因

## 五、下周决策（最多 3 条，可行动）
1. 加码 [x]，预期 [指标] 提升 [y]
2. 停止 [x]
3. 验证 [新假设]

## 六、阻塞/求助
- [需要谁/什么资源]
```

## 硬性规则
- **决策不超过 3 条**，多了等于没决策。
- 每条决策必须有「预期指标」—— 下周复盘时回来验收。
- 淘汰清单和加码清单**同等重要**：不做减法，系统会臃肿。
