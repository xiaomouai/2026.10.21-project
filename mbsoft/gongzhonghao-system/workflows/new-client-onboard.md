# 新客户从 0 到 1 搭建流程

> 适用于：帮企业客户搭建「AI 智能体系统 + 内容获客」的完整交付。
> 时间跨度：建议 4-6 周。

## 阶段总览

```
第 1 周：诊断 + 定位
第 2 周：知识库 + 选题体系
第 3 周：内容启动 + 私域承接
第 4 周：转化跑通 + 归因上线
第 5-6 周：优化 + 交接 + 归档
```

---

## 第 1 周 · 诊断 + 定位

**目标：搞清楚「卖什么、卖给谁、卡在哪」。**

1. **业务诊断**（调用 `gzo-diagnosis`）
   - 采集客户现有数据：流量、线索、成交、产品形态。
   - 定位三角中最堵的环节 → 确定本次项目主目标。
2. **客户画像**
   - 理想客户：行业/规模/痛点/决策链。
   - 记录到 `knowledge/` 作为后续选题依据。
3. **产品梳理**（调用 `gzo-product`）
   - 三级产品结构：引流品/核心品/利润品。
   - 定价锚定「客户获得价值」，不锚定成本。
4. **交付物**：《定位与策略文档》

---

## 第 2 周 · 知识库 + 选题体系

**目标：把客户的行业知识、案例、话术结构化。**

1. **搭建知识库**
   - `knowledge/topic-atoms.md`：从客户业务提炼选题原子（题材×痛点×角度）。
   - `knowledge/objection-handling.md`：历史客户异议 + 应对。
   - `knowledge/cta-library.md`：对应三级产品的 CTA。
2. **选题池**：储备 20-30 个选题假设（调用 `gzo-topic`），标注类型（流量/信任/销售/产品）。
3. **模板化**：把 `templates/` 里的模板适配客户品牌调性。
4. **交付物**：知识库 v1 + 选题池 + 模板套件

---

## 第 3 周 · 内容启动 + 私域承接

**目标：开始稳定产出，跑通「阅读 → 线索」。**

1. **内容启动**（调用 `gzo-content` + `gzo-publish`）
   - 每周 3 篇，覆盖「痛点/方法/案例」三类。
   - 全部登记 `content-log.csv`。
2. **私域承接搭建**（调用 `gzo-convert`）
   - 设计 24h 承接 SOP。
   - 配置自动欢迎语、价值资料、跟进话术。
3. **分发渠道**（调用 `gzo-traffic`）
   - 先跑自有 + 推荐渠道（免费），再评估付费。
4. **交付物**：首批内容 + 承接流程上线

---

## 第 4 周 · 转化跑通 + 归因上线

**目标：看到「内容 → 线索 → 成交」的完整链路。**

1. **转化跑通**（调用 `gzo-convert`）
   - 成交话术打磨，异议应对实战。
2. **归因上线**（调用 `gzo-data`）
   - 全部台账就位：`content-log` / `lead-log` / `deal-log`。
   - 每日采集 + 日报。
3. **第一批数据**：判断哪个选题/渠道最有效。
4. **交付物**：归因报表 v1 + 首批线索/成交

---

## 第 5-6 周 · 优化 + 交接 + 归档

**目标：把系统交给客户自己能跑。**

1. **优化**（基于第 4 周数据）
   - 淘汰低效选题/渠道。
   - 迭代产品（客户反馈 → 需求清单）。
2. **交接**
   - 知识库、模板、SOP 全部交付客户。
   - 培训客户团队跑日流程。
3. **归档**（调用 `gzo-archive`）
   - 项目全过程沉淀为案例素材 → 反哺自身获客内容。
   - 这是「交付案例 → 流量」回路的关键一步。
4. **交付物**：交接包 + 案例素材 + 持续迭代建议

---

## 关键成功因素

1. **第 1 周诊断不能省** —— 定位错了后面全错。
2. **第 4 周归因必须上线** —— 没有数据就无法优化，项目会变成「做做看」。
3. **每个阶段都有可交付物** —— 客户随时能看到进展。
4. **项目本身要成为案例** —— 最终沉淀的内容，是下一单的获客弹药。

> 完整 Skill 调用链：
> `gzo-diagnosis` → `gzo-product` → `gzo-topic` → `gzo-content` → `gzo-publish`
> → `gzo-traffic` → `gzo-convert` → `gzo-data` → `gzo-archive`
