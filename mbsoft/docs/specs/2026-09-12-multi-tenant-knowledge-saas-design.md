# 多租户知识付费 SaaS 设计

日期：2026-09-12

## 产品目标

创建独立 Next.js 项目 `xiaobao-saas`。平台向创作者收固定月租，创作者创建自己的店铺、多个买断或订阅商品以及付费文章；读者注册后完成模拟微信支付，系统自动生成订单并授予阅读权益。

首版验证的是产品和软件流程，不产生真实扣款、分账或收入。所有模拟付款必须明确标记。

## 参考与差异

参考小报童的“专栏商品 → 付费 → 订阅列表 → 持续阅读”路径，以及创作者侧的内容、订单和订阅者管理。项目不复制小报童品牌、页面、文案或平台币体系。

首版只做 SaaS 必需闭环，不做精选市场、算法推荐、社群、合伙人分销、优惠券、兑换码、邮件/微信推送、退款和平台代收分账。

## 商业模型

- 创作者套餐：99 元/月，模拟支付后开通 30 天租期。
- 平台不抽取读者订单佣金。
- 读者订单未来由每个创作者绑定自己的微信支付商户号直接收款。
- 首版用 `wechat_mock` 模拟创作者租金和读者付款，订单与权益逻辑按真实回调方式设计。
- 创作者租期到期后，后台停止发布和新销售，既有读者仍能阅读已购内容，避免损害消费者权益。

## 角色与权限

### 平台管理员

查看租户、租期、店铺、商品、订单总量和模拟交易记录。首版使用预置管理员账号，不做复杂权限编辑。

### 创作者

注册并开通 SaaS 租期；设置店铺名称和简介；创建、编辑、上架多个商品；为商品发布文章；查看自己店铺的订单、销售汇总和订阅者。不能读取其他创作者数据。

### 读者

注册登录；浏览任意已上架店铺与商品；创建并支付自己的订单；查看已购商品、订阅期限和付费文章。不能读取其他读者订单。

同一账号首版只拥有一种业务角色：创作者或读者。平台管理员独立。

## 商品模型

- 买断商品：一次支付，永久访问该商品下已发布和未来发布的文章。
- 订阅商品：一次支付获得 30 天访问；续订从“当前到期日”和“支付时间”较晚者顺延 30 天。
- 商品字段：名称、slug、简介、适合人群、价格（整数分）、模式、状态、所属店铺。
- 文章字段：标题、摘要、正文、标签、状态、发布时间、所属商品。
- 商品详情公开展示简介、作者、价格、更新数量、试看文章和购买规则；正文只在服务端确认权益后返回。

## 核心流程

### 创作者租用

创作者注册 → 创建店铺 → 创建 SaaS 租金订单 → 模拟微信支付 → 开通 30 天租期 → 创建商品与文章 → 上架销售。

### 读者购买

进入 `/s/[storeSlug]` → 浏览多个商品 → 查看 `/s/[storeSlug]/p/[productSlug]` → 注册或登录 → 服务端按当前价格创建订单 → 模拟微信支付 → 原子更新订单与权益 → 进入已购文章。

### 内容交付

创作者发布文章 → 商品页立即出现更新 → 有效买断/订阅读者可阅读 → 未购买用户只能看标题、摘要和明确购买入口。

## 页面

### 公共与读者端

- `/`：平台说明、创作者入驻和示例店铺入口。
- `/register`、`/login`：选择创作者或读者身份并认证。
- `/s/[storeSlug]`：创作者独立店铺和多商品列表。
- `/s/[storeSlug]/p/[productSlug]`：商品详情与文章目录。
- `/checkout/[orderNo]`：模拟微信收银台。
- `/library`：读者已购商品、订阅期限和订单。
- `/read/[articleId]`：服务端鉴权的阅读页。

### 创作者端

- `/creator`：租期状态、商品数、订单数和销售额概览。
- `/creator/billing`：SaaS 月租订单与模拟付款。
- `/creator/store`：店铺资料。
- `/creator/products`：商品列表、新建与编辑。
- `/creator/products/[id]/articles`：文章列表、新建、编辑与发布。
- `/creator/orders`：本店订单和订阅者。

### 平台端

- `/admin`：租户、租期、店铺和订单汇总。

## 数据边界

使用本地 SQLite 持久化 MVP 数据；所有租户业务表均包含或可追溯到 `tenant_id`。服务端从当前会话确定用户与租户，不能接受浏览器提交的 `tenant_id`、价格、订单状态或权益。

核心表：`users`、`sessions`、`tenants`、`saas_subscriptions`、`stores`、`products`、`articles`、`orders`、`payments`、`entitlements`。金额统一使用整数分，订单保存商品名称与价格快照。

正式公网多实例部署前必须把 SQLite 迁移到 PostgreSQL 或托管关系数据库；首版本地实现不宣称具备生产级横向扩展能力。

## 安全与一致性

- 密码使用 `crypto.scrypt` 和随机盐；会话 Cookie 使用 `HttpOnly`、`SameSite=Lax`。
- 每个创作者查询与写入必须验证资源所属租户。
- 每个读者订单、权益和文章访问必须验证当前用户。
- 支付使用幂等事务：唯一支付流水、订单状态更新、权益发放必须同时成功或同时失败。
- 模拟支付仅在 `WECHAT_MOCK_ENABLED=true` 时开放。
- 租户 slug、店铺 slug 和商品 slug 均设置唯一约束与格式校验。
- 付费正文不得出现在未授权页面 HTML 或 API 响应中。

## 示例数据

内置一个可删除的示例创作者店铺“增长手记”，包含：

- 买断商品“小红书首单验证手册”，99 元，2 篇目录内容。
- 订阅商品“每周获客实验”，49 元/月，2 篇目录内容。

示例数据明确标记为演示，不显示虚假销量、评价或收入。

## 验收标准

1. 独立项目可以单独安装、启动、测试和构建，不依赖当前 `mbsoft` 运行代码。
2. 创作者能注册、模拟支付月租、创建店铺、创建两个模式的商品并发布文章。
3. 未开通或已过期租期的创作者不能发布或开启新销售。
4. 读者能注册、浏览多商品店铺、按服务端价格创建订单并模拟支付。
5. 买断权益永久有效；订阅购买和续订正确计算 30 天期限。
6. 未购买者无法获取付费正文，购买者可以立即阅读。
7. 创作者只能看到自己店铺的商品、文章、订单和订阅者。
8. 读者只能看到自己的订单和内容库。
9. 重复支付不会重复发放权益或延长订阅。
10. 平台管理员能查看租户和交易汇总，但不伪装模拟数据为真实营收。
11. 桌面和移动端均可完成注册、购买和阅读主流程。

## 实施顺序

1. 创建独立 Next.js 项目、数据库和三角色认证。
2. 先完成公共店铺、商品详情和视觉方向，提供首个可见预览。
3. 完成创作者租用、商品和文章管理。
4. 完成读者订单、模拟支付、权益与阅读。
5. 完成创作者订单视图和平台汇总。
6. 运行数据隔离、越权、幂等、构建和浏览器闭环验证。

## 明确不做

- 不接真实微信支付、自动续费、退款、分账或提现。
- 不做平台币、优惠券、兑换码、分销、评论、社群和消息投递。
- 不做富文本编辑器或媒体上传；首版文章使用标题、摘要、正文和标签表单。
- 不复制小报童商标、素材、页面布局或受版权保护的文案。
