# 单商家知识付费交易闭环设计

日期：2026-09-12

## 目标与边界

在现有 Next.js 14 项目中，把 `/store` 升级为单商家知识付费交易系统。用户可以注册、登录、浏览商品、创建订单、模拟微信支付、支付后自动获得商品或会员权益、查询订单和访问已购内容。

第一版不接真实资金接口。支付页面和订单必须明确标记“模拟支付”，不能把模拟订单或本地数据称为真实成交。验收标准是：新用户能在浏览器完成注册到内容解锁的本地流程；重启后仍能查询订单与会员状态；未付款或未登录用户无法读取付费正文。

## 技术方案

采用“现有项目增量升级 + Next.js Route Handlers + Node 内置 SQLite”：

- 参考 [nextjs/saas-starter](https://github.com/nextjs/saas-starter) 的认证、结账、订单和订阅数据流，以及 [vercel/commerce](https://github.com/vercel/commerce) 的商品信息层级；两者均为 MIT 许可，不复制品牌或整套 UI。
- 商店运行时代码全部使用 Next.js 和 Node.js 标准库，移除对 `store.py` 命令桥接的依赖。
- 使用当前 Node 22 的 `node:sqlite`，不新增 ORM、认证框架或支付 SDK。
- 商品配置是名称、价格、权益和内容映射的唯一来源；订单保存成交时的名称与价格快照。

不采用纯前端状态，因为订单和权益必须持久化；暂不采用 PostgreSQL，因为本地模拟支付不需要额外部署复杂度。

## 用户路径

1. 用户从小红书或其他渠道进入 `/store` 浏览商品。
2. 进入商品详情，查看价格、交付、适合人群和试看。
3. 点击立即购买；未登录则先注册或登录，随后返回商品。
4. 服务端按当前商品价格创建唯一待支付订单。
5. 用户进入模拟微信收银台并点击“模拟支付成功”。
6. 服务端在一个幂等事务中写支付记录、更新订单并发放权益。
7. 成功页展示订单号、金额、权益结果和内容入口。
8. 账户中心展示订单历史、已购内容和会员到期日。

## 页面

- `/store`：商品列表、会员方案和登录状态。
- `/store/product/[slug]`：详情、试看和立即购买。
- `/store/register`、`/store/login`：认证并支持安全的 `returnTo`。
- `/store/checkout/[orderNo]`：仅订单所有者可见的模拟微信收银台。
- `/store/payment/success/[orderNo]`：支付结果和交付入口。
- `/store/account`：会员状态、已购内容和订单历史。
- `/store/learn/[slug]`：服务端验证权益后返回正文。

首版不新增后台 UI。订单已经持久化在数据库；实际运营需要人工管理时再单独设计后台。

## 商品与会员

| 商品 | 单价 | 权益 |
|---|---:|---|
| 小红书账号诊断 | 99 元 | 永久解锁交付页 |
| 小红书内容方案 | 299 元 | 永久解锁交付页 |
| 7 天获客冲刺 | 1,999 元 | 解锁服务交付入口 |
| 月度会员 | 99 元/月 | 会员内容访问一个月 |

这里的订阅是按订单续期，每次模拟付款将到期日顺延一个月，不做自动扣款。真实自动续费需等微信支付委托代扣资质确定后另行实现。

## 数据模型

- `store_users`：唯一邮箱、密码哈希、创建时间。
- `store_sessions`：令牌哈希、用户、到期时间。
- `store_orders`：订单号、用户、商品 slug、商品名与价格快照、状态及时间。
- `store_payments`：唯一流水号、订单、渠道 `wechat_mock`、金额、状态及回调时间。
- `store_entitlements`：用户、商品、来源订单、解锁及到期时间。
- `store_memberships`：用户、状态、当前周期起止时间、来源订单。

订单状态仅为 `pending`、`paid`、`closed`。金额使用整数分。支付事务必须校验订单归属与金额，并原子完成支付记录、订单更新和权益发放。重复调用返回同一结果，不能重复延长会员。

仅按真实查询建立索引：唯一邮箱、订单号、支付流水号，以及用户订单和用户权益索引。

## 认证与安全

- 密码使用 Node `crypto.scrypt` 加随机盐；不保存明文密码。
- 会话使用高熵随机令牌，数据库只保存 SHA-256 摘要。
- Cookie 使用 `HttpOnly`、`SameSite=Lax`，生产 HTTPS 增加 `Secure`。
- 服务端决定价格、支付状态和用户身份，不信任浏览器提交值。
- 订单、结账和内容接口均验证当前用户及资源归属。
- `returnTo` 只允许 `/store/` 开头的站内路径。
- 模拟支付仅在 `WECHAT_MOCK_ENABLED=true` 时开放，关闭后不能通过直接请求绕过。

## 接口

- `POST /api/store/register`、`POST /api/store/login`、`POST /api/store/logout`
- `GET /api/store/me`
- `POST /api/store/orders`、`GET /api/store/orders`
- `GET /api/store/orders/[orderNo]`
- `POST /api/store/payments/wechat/mock`

当前数据库中的邀请码和既有权益记录均为零，因此移除邀请码入口；新订单支付后直接发放权益。

## 错误与恢复

- 重复邮箱、错误密码、未知商品、越权订单返回明确但不泄密的错误。
- 重复创建待支付订单可以存在，但只有已支付订单发放权益。
- 重复支付请求幂等返回，不创建第二条有效支付或重复延期。
- 数据库事务失败时订单保持原状态，并显示可重试提示。
- 未登录访问结账或账户时跳转登录并保留安全返回路径。
- 未授权访问内容时不输出付费正文。
- 模拟支付关闭时明确显示暂不可支付，不伪造成功。

## 验证

1. 注册后建立会话，错误密码不能登录。
2. 提交伪造价格时，订单仍使用服务端价格。
3. 其他用户无法读取或支付不属于自己的订单。
4. 支付前无法访问内容，支付后立即可以访问。
5. 同一订单重复支付不会重复发放权益或延长会员。
6. 会员复购从当前到期日或付款日中较晚者续期。
7. 事务失败不会留下“已支付但未发权益”的部分状态。
8. `npm run build` 成功，现有非商店页面不受影响。
9. 浏览器走通：注册 → 商品 → 订单 → 模拟付款 → 查询订单 → 打开内容。

## 明确不做

- 不把模拟付款称为真实收入或真实成交。
- 不接真实微信支付、退款、分账、发票或自动扣款。
- 不做多商家、分销佣金、优惠券、购物车或库存。
- 不做短信登录、第三方登录、视频托管、直播或考试。

## 切换真实微信支付

具备商户号、API v3 密钥、商户私钥、证书序列号、HTTPS 域名和对应产品权限后：用微信 Native/H5/JSAPI 下单替换模拟接口，增加回调验签与解密，并且仅由验签通过、金额一致的回调触发现有支付事务。订单和权益模型保持不变。
